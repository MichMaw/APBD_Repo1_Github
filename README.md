1. Fast forward występuje gdy na głównym branchu niemamy commitów od momentu rozwidlenia (niepowstaje przytym dodatkowy merge commit)
2. Merge commit występuję gdy oba branche mają commity, git tworzy  dodatkowy commit merge
3. Merge zachowuje historię gałęźi i robi merge commit a Rebase przenosi commity z jednej gałęzi na drugą
4. Konflikt został rozwiązany powracając do orginalnego rozwiązania (polegał na zmianie wartosci domyślnych returna metody przy nieprawidłowych argumentach)
